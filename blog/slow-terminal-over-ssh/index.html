Why typing over SSH got slow, and what 0.5.1 changes

Noon 0.5.1 is out. Most of it is one fix, for terminals on remote machines that got slow after 0.4.1.

Snehith NayakNovember 23, 20262 min read

What happened #

After 0.5.0 shipped, typing in a task’s terminal on a remote Linux machine got slow enough to be unusable. Keys showed up late, and resizing, resuming and scrolling dragged too. The machine was a big workstation that a lot of people share. It had also been faster a few releases earlier, which turned out to be the useful clue.

What 0.4.1 added #

In 0.4.1 we made Stop end the programs an agent starts, like a dev server it leaves running in the background. To know what those are, the small helper Noon runs on each machine keeps a record for every task. It checked the task’s own process tree twice a second, and every five seconds it went through every process on the machine looking for ones working inside the task’s folder [1].

That ran on the same loop that carries the terminal’s bytes. On a laptop, or on the test machines we use, it takes almost no time, so nothing looked wrong. A shared workstation has far more processes to go through, and for each one the helper read /proc/stat again to get the machine’s boot time, which is the same number every time. While it did all that, your keystrokes waited.

The fix #

0.5.1 moves that bookkeeping onto a thread of its own, so the terminal never waits for it. It reads the boot time once. And it only looks at your own processes: anything your agent started runs as you, so other people’s programs were never candidates (running as root, it still looks at everything). Stop ends the same things it did before [1].

What we haven’t measured #

We couldn’t reproduce the slowness here, because our test machines don’t have hundreds of other people’s processes on them. So this is the most likely cause, not a proven one. If typing over SSH is still slow for you on 0.5.1, choose Help → Troubleshooting → Save Diagnostics while it’s slow and send us the file, or open an issue.

Getting the fix onto a remote machine #

Updating Noon on your Mac isn’t enough on its own. The helper on the remote machine lives in your ~/.noon (no admin needed), and it only replaces itself when nothing is running there, so an update never cuts off a working agent. Stop that machine’s tasks, close Noon’s terminals on it, reconnect, then Resume each task. The agents carry on in the same conversations.

Also in 0.5.1 #

  • A task merged through a pull request on GitHub now reads “In origin/main” after you fetch, instead of looking unmerged until you pull.
  • Claude Code options that would take an agent out of Noon’s terminal or its workspace, like --worktree, --tmux or --teleport, are refused when a task starts.
  • The suggested merge order is gone from the Agents list and the Repository pane.
  • There’s no menu bar icon anymore. Everything it had is in the regular menus.
  • New Terminal opens in the project’s folder, not in a task’s workspace.
  • Closing the last terminal no longer shows a “No such terminal” alert.
  • The map stays still while you move or resize the window, and a project hidden from the map looks hidden in the Projects list.

The full list is in the release notes [2]. Noon → Check for Updates… offers 0.5.1 from 0.5.0 and earlier.
